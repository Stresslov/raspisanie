# Перенос расписания целиком на GitHub

Подготовлена версия сайта, которая не обращается к прежнему хостингу. Расписание, версии и замены хранятся в `data/school.json` в вашем репозитории; опубликованные PDF — в `data/pdf/`. Просмотр загружает данные с того же GitHub Pages, где открыта страница. Ключи и вход для просмотра не нужны.

## Что сделать сейчас

1. Распакуйте архив **Переезд на GitHub.zip** в отдельную папку.
2. Откройте https://github.com/Stresslov/raspisanie и нажмите **Add file → Upload files**.
3. Перетащите содержимое распакованной папки в окно загрузки: **index.html**, **папку data** и остальные файлы. Содержимое должно попасть прямо в корень репозитория, без дополнительной внешней папки. Путь файла данных в GitHub должен быть именно `data/school.json`.
4. Нажмите **Commit changes**. Дождитесь успешной публикации во вкладке **Actions**.
5. Откройте https://stresslov.github.io/raspisanie/ и обновите страницу. При необходимости нажмите Ctrl+F5.

**На этот раз замены одного index.html недостаточно: обязательно загрузите и папку data.** Если сайт пишет, что data/school.json не найден, проверьте путь и завершение публикации Pages. В архив включены подтверждённые вами 2174 урока для 63 обозначений классов из исходного PDF. У исходных данных нет ограниченного периода, поэтому они повторяются по неделям, пока вы их не обновите.

## Как теперь обновлять расписание и замены

Прежний пароль проверялся на прежнем сервере. В этой версии для сохранения изменений используется **ключ GitHub** с правом записи в этот репозиторий.

1. В GitHub откройте аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Укажите владельца **Stresslov**, задайте название и срок действия ключа.
3. В **Repository access** выберите **Only select repositories → raspisanie**.
4. В **Repository permissions** задайте **Contents → Read and write**. Сохраните ключ.
5. На сайте откройте **Управление**, вставьте ключ в поле «Ключ доступа GitHub» и войдите. Загрузка Excel/CSV, предпросмотр, публикация, отдельные файлы и PDF работают в том же разделе.
6. Для работы с заменами войдите этим или другим разрешённым ключом внизу раздела **Замены**. Плашка требуемых замен появляется только после этого входа.

Не присылайте ключ в чат и не загружайте его в репозиторий. В интерфейсе он используется только в памяти текущей вкладки, отправляется только GitHub API в заголовке авторизации и не сохраняется в localStorage или файлах данных. После закрытия вкладки потребуется новый вход.

Ключ GitHub даёт права на изменение выбранного репозитория, а не только замен. У GitHub Pages нет отдельной проверки школьного пароля и разделения прав на уровне строк расписания. Ключи выдавайте только тем ответственным, которым разрешено изменять репозиторий; ненужный ключ можно отозвать в GitHub.

## Когда изменения увидят все

После нажатия «Опубликовать» данные записываются в GitHub коммитом. Администратор сразу получает подтверждение записи. Остальные посетители увидят обновление **после успешной публикации GitHub Pages**, а не мгновенно. Статус можно проверить во вкладке Actions. Сайт периодически обновляет просмотр автоматически; можно также обновить страницу вручную.

Если другой ответственный успел изменить данные, сайт не затирает их молча: появится сообщение об изменении версии. Сохраните резервную копию своего черновика, обновите данные и повторите нужную правку.

PDF до публикации остаётся во вкладке как черновик. После публикации он доступен всем, как и остальные файлы публичного репозитория. История опубликованных расписаний и замен также остаётся в истории GitHub.

## Что проверено

- 45 автоматических тестов: просмотр, классы/учителя/кабинеты, подгруппы, день/неделя, импорт, прежний API, GitHub-хранилище, авторизация, публикация, отдельные файлы, замены, отмена отсутствия и защита от конфликтов.
- Линтер, проверка типов и производственная сборка Vinext/Vite — успешно.
- Отдельно выполнена проверка DOM именно выдаваемого index.html с настоящими 2174 уроками: запросы просмотра идут только к data/school.json с текущего сайта, публикация — только в GitHub API; прежнего адреса в HTML нет. Все сетевые ответы в автоматических тестах заменены хранилищем в памяти.
- Визуальная проверка в настоящем браузере и запись в ваш GitHub не выполнены: ранее автоматическая проверка разрешений отклонила доступ. Архив подготовлен для ручной загрузки; перенос на действующем адресе завершится после выполнения шагов выше.

Документация GitHub: https://docs.github.com/en/rest/repos/contents и https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site.

После первого переноса **не загружайте исходный data/school.json из этого архива повторно поверх новых изменений**: он вернёт исходные данные и очистит более поздние версии/замены. Для будущих обновлений оформления заменяйте только файлы интерфейса, сохраняя текущую папку data.
