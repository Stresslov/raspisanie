# Проверка обновления на GitHub

Сайт: https://stresslov.github.io/raspisanie/

Это обновление существующего проекта. Оно сохраняет фирменный стиль, расписания классов / учителей / кабинетов, день и неделю, подгруппы, цвета корпусов и электронных уроков, сотрудников без основной нагрузки, подбор замен и кнопку «На экран».

## Обновление

1. Распакуйте «Обновление GitHub для проверки.zip».
2. Откройте репозиторий Stresslov/raspisanie, ветку main и корневую папку, где уже лежит index.html.
3. Через Add file → Upload files загрузите **всё содержимое распакованного архива**, включая папки assets и vendor. Не загружайте ZIP как один файл и не создавайте для обновления дополнительную вложенную папку.
4. Подтвердите обновление файлов кнопкой Commit changes. **Текущую папку data не удаляйте и не заменяйте**: в ней расписание, сотрудники, замены и PDF. В архиве обновления этой папки нет.
5. Дождитесь завершения публикации в GitHub → Actions / Pages, откройте прежнюю ссылку и обновите страницу. На компьютере при необходимости Ctrl+F5.

Одного index.html для этой версии недостаточно: распознавание PDF использует локальные файлы vendor/pdfjs. Остальные файлы также входят в готовый архив. Не проверяйте распознавание через двойной щелчок по локальному HTML: браузер загружает модуль PDF с сайта по HTTPS.

## PDF → исправления → отдельное расписание

1. Откройте «Управление» → «Загрузка и публикация», войдите по своему ключу доступа GitHub. Инструкция создания ключа есть под формой входа. Школьные пароли на GitHub пока не применяются.
2. Сначала нажмите «Скачать резервную копию», чтобы сохранить текущее расписание.
3. В блоке «Распознать расписание из PDF» выберите школьный PDF, такой же, как присланный ранее. Для файла со всеми классами поле «Один класс для всех страниц» оставьте пустым. При необходимости укажите адрес корпуса.
4. Нажмите «Распознать и настроить». Дождитесь окончания; счётчик показывает страницы. Для присланного файла ожидается **2174 урока, 63 класса, 63 страницы**. Есть 49 строк для ручной проверки: обозначения и вакансии в самом источнике не заменяются придуманными ФИО.
5. Выберите класс, проверьте предметы, учителей, кабинеты, время и подгруппы. Исправляйте прямо в таблице; используйте фильтр строк для проверки и массовую замену кода учителя на ФИО. Предупреждения о пропущенных страницах тоже нужно проверить. Поддерживается текстовый PDF, не скан / фотография; предел 20 МБ и 120 страниц.
6. После проверки поставьте подтверждающую галочку и нажмите «Добавить уроки в черновик», затем «Предпросмотр». До публикации изменения видны только в этой вкладке.
7. Вернитесь в «Управление». В поле «Название» блока «Отдельный файл расписания» напишите **Проверка PDF** и нажмите **«Сохранить и опубликовать отдельно»**. Этот вариант появится в списке файлов сверху. «Актуальное» сохранится. Кнопка «Опубликовать для всех» обновляет выбранный файл — для первого теста используйте именно отдельное сохранение.
8. Дождитесь публикации GitHub Pages, откройте сайт в другой вкладке без входа, выберите «Проверка PDF». Проверьте день и неделю, учителя / кабинет, все позиции уроков и пары подгрупп. Просмотр гостями не требует ключа. Для публикации и просмотра актуальных данных нужен интернет.

## Замены

1. Сначала выберите тестовый файл «Проверка PDF». В «Заменах» войдите как ответственный по ключу GitHub.
2. Отметьте отсутствие учителя на выбранную дату и урок. Откройте требуемую замену и проверьте варианты: другая подгруппа → классный руководитель → предмет и корпус. Занятые / отсутствующие педагоги исключаются по действующим правилам; для другой подгруппы действует оговорённое исключение.
3. Назначьте замену. В расписании нового учителя урок должен появиться с жёлтой пометкой «Замена», у исходного — остаться с пометкой «Урок заменяется». Проверьте отмену отсутствия в той же плашке.
4. При необходимости добавьте сотрудника без основной нагрузки и проверьте его доступность для назначения. Список дополнительных сотрудников общий для всех файлов расписания, поэтому для теста используйте настоящего сотрудника либо удалите тестовую запись после проверки.
5. В блоке передачи в МЭШ выберите период и нажмите «Подготовить замены». Пока есть неназначенные или устаревшие уроки, выгрузка заблокирована. После назначения всех замен можно скачать CSV / JSON и проверить список.
6. Выйдите из раздела. Публичный список замен должен остаться видимым, уведомление о требуемых заменах — скрыться.

**Отправка в МЭШ не подключена**, кнопка так и подписана. CSV / JSON — внутренний список, а не обещание совместимости с импортом МЭШ. Подключение потребует официального способа интеграции и доступа школы.

## Что проверяется позднее на школьном сервере

Отдельные логины и пароли с правами «Администратор» / «Ответственный за замены» уже подготовлены в серверной версии. GitHub Pages не исполняет этот серверный код, поэтому здесь вход по ключу GitHub; его права распространяются на репозиторий. Парольные роли проверяются при запуске серверной версии.

## Выполненные проверки

84 автоматических теста пройдены: расписание и подгруппы, приоритеты и занятость замен, сотрудники, GitHub-запись и защита от конфликтов, PDF-черновик, выгрузка замен, интерфейс, установка и серверные роли. Проверки lint, TypeScript и сборка проекта прошли. Распознавание исходного PDF через браузерный движок сравнили с прежними данными: все 2174 урока совпали по классу, дню, номеру, времени, предмету, учителю, кабинету и подгруппе.

Интерфейс проверен через DOM-тесты с подставным хранилищем GitHub. Публикация в ваш реальный репозиторий, визуальный вид в браузере и установка на телефоне в этой проверке не выполнялись; их можно проверить после загрузки архива.
